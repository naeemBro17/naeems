═══════════════════════════════════════════════
1. WHAT I DID
═══════════════════════════════════════════════

FIX 1 — Removed weight cost section from New/Edit Lot form
  The "Weight cost" card in the lot form is gone. Only "Other costs" remains.
  The per-item cost breakdown now shows: Buy + other = landed cost (weight removed).
  The "weight guessed from price" badge and note are also removed.
  The database still stores weight cost data — only the UI input is removed.

FIX 2 — Lot delete no longer blocked by Safety Lock in the UI
  Previously the Delete button was disabled unless the Safety Lock was open.
  Now the button is always enabled (not gated by openUntil).
  The database RPC (inventory_delete_lot) still enforces its own checks — if the
  DB rejects the delete, the error message will show on screen as before.
  The Safety Lock context subscription is kept (useSafetyLock() still called) so
  the context stays intact for other parts of the app.

FIX 3 — Product stock refreshes after order edit
  After saving an edited order, the product list now calls refetchProducts()
  before navigating away. This means when you go to Products after editing an
  order, the stock numbers are fresh — not stale from the last load.

5. DESIGN DECISIONS
═══════════════════════════════════════════════

- For Fix 2: chose to keep useSafetyLock() call (without destructuring openUntil)
  rather than removing the import entirely. This keeps the context subscription
  alive, which is harmless and future-safe.

- For Fix 3: refetchProducts() runs before onSaved() (which navigates away).
  This adds a brief wait (~200ms) before navigation but ensures fresh data.

- After editing an order, the customer's order history (if/when added) will also
