3) FACEBOOK PIXEL & GOOGLE ANALYTICS
--------------------------------------
Both are wired in but OFF until you add an ID — Admin → Settings → "Facebook
Pixel & Google Analytics" (new panel, right under the delivery/bKash one).

What's tracked (never your customer's name/phone/address/email — only
product id/name/price in BDT, quantities, an order's total + order number,
and a typed search term):
  - ViewContent / view_item — a product page opens
  - AddToCart / add_to_cart — from a product card OR the product page
  - InitiateCheckout / begin_checkout — tapping "Checkout" in the cart
  - Purchase / purchase — on the order success page, with the real order
    number as the event/transaction id, so Facebook/Google themselves
    de-duplicate it if the page is ever refreshed — the same order can never
    get counted as two sales
  - Search / search — pressing Enter or picking a suggestion in search
  - PageView / page_view — every in-app navigation, not just the first load
    (this is a single-page app, so without this only the very first page
    would ever count)
Never fires anything on /admin or /wholesaler-access.

How to set it up (step by step for Naeem):
  Facebook Pixel:
    1. Go to business.facebook.com → Events Manager → "Connect Data
       Sources" → Web → Facebook Pixel → give it a name.
    2. Skip the "install code" step (choose "Manually add code" if asked,
       but no code needs pasting anywhere else) — just copy the Pixel ID
       number it shows you (looks like 123456789012345).
    3. Paste it into Admin → Settings → Facebook Pixel ID → Save.
    4. To confirm it's working: Events Manager → your Pixel → "Test Events"
       tab, then open the site on your phone/browser — you should see
       PageView events appear live within a few seconds.
  Google Analytics 4:
    1. Go to analytics.google.com → Admin → Create Property → follow the
       prompts (choose "Web" as the platform).
    2. It gives you a Measurement ID that looks like G-XXXXXXXXXX.
    3. Paste it into Admin → Settings → Google Analytics Measurement ID →
       Save.
    4. To confirm: Analytics → Reports → Realtime — browse the site
       yourself and you should see yourself show up as an active user
       within about 30 seconds.


4) PRODUCT LINK PREVIEWS (Facebook/WhatsApp)
-----------------------------------------------
How it works: this site is a single-page app, so a link-preview bot
(Facebook, WhatsApp, etc. — they don't run JavaScript) normally only ever
sees the one generic description in index.html, never a specific product's
real name/price/photo. Added a small Vercel function (api/product-og.ts)
that only kicks in for a request whose User-Agent matches a known
preview-bot (Facebook, WhatsApp, Twitter, Telegram, Slack, LinkedIn, Discord
— Googlebot deliberately excluded, exactly as asked, since Google already
handles this app correctly on its own). A real visitor's browser is never
touched by this — same app, same speed, zero difference.
I tested the HTML-generation logic directly (mocked the database response
and an unsafe/malicious slug) and it behaved correctly both times — but the
actual routing rule only exists on Vercel itself, so I could not curl-test
it against a live deployment from here.
  How Naeem can test after this is deployed:
    1. curl -A "facebookexternalhit/1.1" https://naeems-all.vercel.app/product/<any-real-product-slug>
       → should return a small HTML page with that product's real name,
       price and photo in the og:title/og:image tags (view-source or just
       read the curl output).
    2. Better: paste a product link into Facebook's Sharing Debugger
       (developers.facebook.com/tools/debug/) and click "Scrape Again" — it
       should show that product's real photo and price, not the generic
       site card.
Also gave the home page a proper og:site_name and Twitter card tags (it
already had a real 1200×630 share image and title/description from an
earlier batch — just completed what was missing).
