PART 2 — Inline YouTube video
Root cause: the video row just did `window.open(url, '_blank')`. Added
src/lib/youtube.ts to parse a video id out of watch/youtu.be/shorts/live
URLs (any host or shape it doesn't recognise returns null); the product
detail page now opens the existing shared Modal with a 16:9 embedded
iframe (youtube-nocookie.com, autoplay) when an id is found, and falls
back to the old open-in-new-tab behaviour when it isn't — so a bad/foreign
URL can't break the page.
Verified: tested against two real products with real youtu.be URLs from
the live database (read-only). Confirmed via DOM/computed-geometry checks
— modal opens with a correctly-sized 400×225 (exact 16:9) iframe, correct
embed URL, scroll lock and focus trap engage/release correctly, close
button works. Also unit-checked the parser against 8 URL shapes (watch
w/params, youtu.be, shorts, m.youtube.com, a non-YouTube host, garbage
text, empty string, a YouTube URL with no video id) — all correct.
Screenshot capture itself became unreliable specifically while the real
YouTube iframe was live (see section 3) — a tooling/sandbox issue, not
something in the app; DOM-level verification is solid.

PART 3 — Filter/browse (Brand + Skin Type)
Built and wired up the "Filters coming soon" placeholder button. New
useProductFilters hook (src/hooks/useProductFilters.ts) + FilterSheet
component (src/components/viewer/FilterSheet.tsx), opened from the
existing filter button, using the existing BottomSheet + the admin
product editor's own ChipGroup/skinFields.SKIN_TYPES (reused, not
duplicated). Filters apply on top of the existing search+category result

filter button shows a small neutral count badge when any filter is
active; the empty state gets its own "No products match these filters" /
Clear filters action, checked before the existing search/category empty
states.
Verified live end-to-end against the real catalog: opened the sheet, saw
real Brand chips (Aveeno, La Roche Posay) and all 6 Skin Type chips,
selected Aveeno → grid correctly dropped to 1 product; added a Skin Type
with no overlap → correctly showed 0 results with "Clear filters"; clicked
it → grid and badge both reset to the full 104-product catalog; reopening
the sheet correctly remembers the last-applied selection. No console
errors during any of this.
Deferred (per the task's own "build what's included completely rather

4. WHAT I FOUND ALONG THE WAY
--------------------------------------------------------------------
- Two separate orange tokens exist site-wide: --color-accent (#FF7A45,
  most customer-facing UI) and --color-primary (#F05020, admin forms,
  auth modal, generic .button--primary). Both are "the brand orange" to a
  user but are literally different hex values in a few places they sit
  near each other (e.g. AccountSheet's button--primary next to
  accent-coloured icons). Not a rule violation, just worth eventually
  picking one.
- ChipGroup (the multi-select chip row) lives under
  components/admin/edit-sheets/ even though it's a plain, generic,
  presentational component — Part 3's customer-facing FilterSheet now
  imports it from there too. Reused as-is rather than relocating it, to
  avoid an unrelated refactor; a future session could move it to
  components/shared/ now that it has a non-admin consumer.
- .save-badge (red, product detail page's own bigger save pill) and
  .product-card__save (grid card's small pill, fixed this batch) are two
  separate badge implementations for the same "Save X%" concept — the
  detail one was already non-orange (uses --color-danger), so nothing to
  fix there, just noting the duplication.

--------------------------------------------------------------------
5. DESIGN DECISIONS
--------------------------------------------------------------------
- Where a "selected/active" element could show on the same screen as the
  actual primary action (chips, nav tabs, badges), I used the site's
  existing inverted neutral pattern (near-black bg / near-white text,
  flips correctly in dark mode) rather than inventing a new treatment.
- Kept the whole admin "Edit Mode" family (toggle, top bar, drag states,
  the card menu's "Edit Product" item) orange — it's a deliberate,
  self-contained, customer-invisible visual language ("you are editing"),
  not overuse of the same accent for unrelated things.
- Carousel/pagination dots that sit over a photo (hero banner, bento
  swipe-stack) went white/near-white rather than near-black, since they
  need to read against a photo, not the page background.
- Part 3's "Show Results" button uses --color-accent (matches cart
  button / Add to Cart / hero CTA — the customer-facing accent) rather
  than --color-primary, for consistency with the rest of the viewer.
- Filter sheet drafts locally and commits on Apply (rather than filtering
  live as each chip is tapped) so backing out of the sheet never leaves
  the grid in a half-changed state, and so the "Show N results" button
  can double as a live preview.
