PART 1 — One set of status names
  - One module holds every status name, colour, icon and step:
    supabase/functions/_shared/orderTracking.ts. The website, both
    Steadfast functions and the Telegram alert all read it. Nothing in
    the database was renamed; the old values are mapped (table in
    section 3).
  - "Shipped" is gone from every screen; it is now "In transit".
  - Pill colours (light and dark): Processing amber, Confirmed blue,
    In transit purple, Out for delivery teal, Delivered green,
    Cancelled red, Returned grey.
  - Earlier steps fill in by themselves. Example: a parcel marked
    Delivered with no "rider" update still shows all five steps done.
  - Tracking updates are saved in a new table, order_tracking_events,
    by both the 3-hourly refresh and the on-demand refresh. The same
    update twice is saved once (one key per time + text).
  - Steadfast's messages are turned into short friendly English:
      "Consignment created by Sender(API)."      → Handed to Steadfast
      "…status has been updated as Pending"      → Picked up by Steadfast
      "Consignment sent to MIRPUR WAREHOUSE…"    → On the way to the Mirpur sorting centre
      "…received at SAVAR WAREHOUSE. By Sorter…" → Reached the Savar sorting centre
      "Consignment sent to NIKUNJA…"             → On the way to Nikunja delivery hub
      "…received at PALLABI."                    → Arrived at Pallabi delivery hub
      "Assigned to rider."                       → Out for delivery with a rider
      "…marked as delivered by rider."           → Delivered
    Unknown messages are shown cleaned (no phone numbers, IDs or codes).
  - IMPORTANT, found while doing this: Steadfast's update list also
    contains YOUR OWN edits, e.g. "Changes: COD '4079' to '0'. By User
    Naeem(1380201)", "Address change requested … by the merchant". Until
    now the customer's order page showed these to the customer. They are
    now hidden from customers: in the Steadfast function AND again on the
    page, so they stay hidden even before the function is redeployed.
  - Payments show up as updates for the customer: "Payment received —
    ৳1,000 with bKash. Thank you!" (never the TrxID). This needs the
    database addition (section 5).
  Proof: 25 unit tests in src/lib/batch35.test.ts, built on the real
  Steadfast wording. They cover every status, the auto-filled steps,
  no duplicates, the hidden internal edits, cleaned text, payments as
  updates and translating twice giving the same words.

2. WHAT STEADFAST REALLY GIVES US
============================================================
  I read the existing function code and, read-only, the real tracking
  answers saved in our own database (no new Steadfast call):
  - /status_by_cid → one status word (in_review, pending, hold,
    delivered, delivered_approval_pending, partial_delivered, cancelled,
    exceptional, unknown …).
  - /trackings_by_invoice → a list of short English texts with a time
    (examples in Part 1).
  - "Assign to rider" DOES come through: the text "Assigned to rider."
    (or "Assigned to rider by self-scan at the hub."). That fills Out
    for delivery for real.
  - The rider's NAME and PHONE do NOT come through. No text I saw
    contained them, and the API has no rider field. So the rider row is
    built and switchable, but it will stay hidden until Steadfast sends
    a name and number. Nothing is faked.
  How each step fills:
    Order placed — the order exists (time = order time)
    Confirmed — you confirmed it (time from History)
    In transit — booked on Steadfast or marked by hand (time from History)
    Out for delivery — newest courier update is "Assigned to rider"
      (a later "received at hub" moves it back to In transit)
    Delivered — Steadfast says delivered / delivered_approval_pending /
      partial, or you marked it delivered
  Cancelled = cancelled on the site. Returned = Steadfast cancelled*
  (the parcel comes back). Hold / exceptional stay In transit with a
  calm note.
