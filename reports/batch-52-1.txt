1. WHAT I DID
---------------------------------------------------------------------
ROOT CAUSE (plain words)
The cart has a safety check that runs each time the cart or the order
summary opens: it reads the stock of every item and removes anything
that is "just sold out". That check looked ONLY at the stock number. It
never looked at "Keep selling when out of stock".
- Customers and wholesalers were safe: the database hides the stock
  number of keep-selling products from them (Batch 51), so the check had
  no number to act on.
- You (and any staff login) are NOT shown the hidden version — staff see
  the real number. With Inventory mode On that number is 0, so the cart
  removed the item with "Sorry, … just sold out. We've updated your
  cart." That is exactly what you saw, for products with and without
  options.
The database itself was right all along: I ran a real order for the
Cicaplast Baume B5+ (both sizes) on the live database as the test
customer inside a transaction that was undone — it was accepted, marked
"buy after order", and the 3 missing units were recorded as "sold
without stock". Nothing was kept, and the order-number counter was put
back.

WHAT WAS FIXED
- One shared rule (src/lib/buyRule.ts) now answers "can this be bought,
  and how many?" for every screen: Keep selling ON → yes, up to the
  order limit (4) for customers, no limit for wholesalers / admin;
  Keep selling OFF → only what is in stock. An option (variant) always
  follows its product's switch. The cart check now uses it, so it can
  never disagree with the product page again.
- Customers still never see the stock number of keep-selling products
  (unchanged: the database hides it).
- Edit product → Variants, with Inventory mode On: the switch next to
  each option is gone (it was the option's "in stock" flag; Inventory
  mode rewrites it from lots, which is why it snapped back). The row now
  says "From lots: 0". Inside the option editor, "In Stock" shows Yes/No
  as text and "Stock Quantity" is greyed out, with the hint "Inventory
  mode is On: the stock number comes from lots (whole packs). Add a lot
  to change it." With Inventory mode Off both work exactly as before.

WHY BATCH 51'S TESTS DID NOT CATCH THIS
Batch 51's browser tests rewrote every product the shop loaded into the
customer's version (stock number hidden), and they only ever shopped as
a customer — never as the admin. So the cart check never met a real 0.
Its database tests placed orders directly, never through the cart. The
gap was "what a staff login sees in the cart", and no test looked there.

4. WHAT I FOUND ALONG THE WAY
---------------------------------------------------------------------
- Admin New order: a keep-selling item at stock 0 shows red "Sold out —
  none left in stock" and asks "Sell anyway?". It works (saying yes
  saves it and records the shortage), but the words are wrong for
  keep-selling products. Fixing it properly needs a small change in the
  database's admin_create_order, so I left it as asked ("unchanged").
- Products page "Stock Status" select is still saved by the form while
  Inventory mode is On (the database overwrites it from lots). Harmless,

- Possibly duplicated / weak fields (NOT removed): "Stock Status" and
  "Stock Quantity" both describe stock, and with Inventory mode On
  neither can be changed here; the product's own Region / Size and the
  first option overlap in meaning (explained by the long helper text).
- The repo has many changed screenshot files from older batches
  (reports/batch-34…50, public/sitemap.xml) left over from earlier test
  runs. I did not commit them.

5. DESIGN DECISIONS
---------------------------------------------------------------------
- Sections as white cards with a short bold heading, same look as the
  other admin cards; light and dark mode use the admin colours.
- Right column = things you glance at or change rarely (Active,
  Featured, photos, SKU); left = what you edit most (name, prices,
  stock, variants, texts). Prices sit in one row of three on a computer.
- On a phone "Shop" (Active / Featured) comes right after Basics so
  hiding a product is near the top, as you asked for Live.
- Brand and Category share a row on a computer and stack on a phone.
- The variant row shows the offer price (what customers pay) in
  near-black with the retail price struck through, like the shop.
- With Inventory mode On, read-only stock shows as text or a greyed box
  — never a switch that looks like it works.


---------------------------------------------------------------------
6. INDUSTRY-LEVEL SUGGESTIONS (highest impact first)
---------------------------------------------------------------------
1. Test as every role. Weak now: shop tests mostly shop as a customer.
   Why it matters: this bug only hit staff logins and slipped through.
   Every shop flow test should run once as customer and once as admin.
   Size: medium.
2. Admin New order wording for keep-selling items (see section 4).
   Why: a red "Sold out" makes staff refuse sales the shop wants. Size:
   small (needs a small SQL change).
3. Staff see real stock on the shop pages. Why: it is useful, but it
   means staff and customers see different things; a small "Staff view"
   note on the product page would avoid confusion. Size: small.
4. An "unsaved changes" dot per section on Edit product. Why: on a long
   page it is easy to forget a changed field far below. Size: small.
5. Save % preview under the prices (e.g. "Customers save 14%"). Why:
   catches a typo in the offer price before it goes live. Size: small.
