PART 5 — Brand logos: same size in light and dark, coloured backgrounds fill the card
  - One shared logo component (components/viewer/BrandLogo.tsx) used by
    Home's "Shop by Brand", /brands, the brand page logo plate AND the
    admin Brands preview (which now draws the real shop card, so it
    shows exactly what customers see).
  - The rules (lib/logoProcess.ts):
      * Transparent logo → empty edges trimmed (as before).
      * Solid white or black backdrop (judged from the whole outer edge,
        not just the four corner pixels, so a letter touching a corner
        can't fool it) → the backdrop becomes see-through, spreading in
        from the edges only — never inside letters — with soft
        anti-aliased edges and no halo, then trimmed.
      * Any other solid colour backdrop (blue, yellow…) → the colour is
        KEPT: the whole card takes that colour, same rounded corners, no
        inner box, the same in light and dark (the dark-mode logo slot is
        ignored for these).
      * A picture that is all one colour is never treated as a backdrop.
      * Anything else (e.g. a photo) → shown as it is.
  - Both logos are fitted into the same box with the same padding, so
    switching light/dark changes colours only, never size or position.
  - HOW EXISTING LOGOS WORK WITHOUT RE-UPLOADING:
      * New uploads are cleaned in the admin before saving (a white/black
        backdrop is removed for good; a brand colour is kept, with a thin
        frame of that colour, so the shop can still read it).
      * Logos already uploaded are cleaned in the shopper's browser, in a
        background worker (off the main thread), only for cards near the
        screen, and the result is stored on that phone — so it's done
        once per phone, not on every visit. Logos that are already clean
        (most of yours) are left exactly as they are.
      * If a logo can't be read (no permission, error, too slow) it is
        shown exactly as today — never a broken image.
  - What changes on the live site: David Beckham, Bio-Oil, Hamilton and
    ILLIYOON (normal logos with a white box behind them) are now the
    same size as their dark-mode twins; Invisible Zinc's card is now
    fully yellow in both modes. Admin helper text updated as asked.
  Proof: Part 5 tests with test pictures inside the test browser

PART 7 — Fast Home
  What I changed:
  - Every page except Home is now its own small file, downloaded only
    when needed: product page, search, brands, brand page, cart,
    checkout, account, orders, policies, admin. Admin's in-page edit
    sheets (banner, bento, browse, product, expert) are only downloaded
    the first time an admin opens one — customers never load them.
  - Morph safety: the product page's file is pre-loaded as soon as the
    phone is idle after the first page appears, and again on touching
    any card. Every in-app navigation waits for the target page's file
    if it isn't there yet (normally it already is), so the card →
    product morph and Back look exactly as before — the transition never
    captures a loading placeholder. The fallback (only on a direct visit
    to a link, for a moment) is the plain page background, no spinner.
  - Home draws the first 8 product cards at once, then the rest 4 at a
    time whenever the phone is idle (each step well under the 50 ms that
    makes taps feel stuck). Coming BACK to Home at a remembered spot
    draws everything at once, so scroll memory and the reverse morph work
    exactly as before (all their tests pass).
  - Fixed the big layout jump (score 0.31): the banner and the Browse
    circles now hold their exact space while the shop's data loads.
  - The Home banner photo is requested from the page's very first lines
    (index.html), instead of after the app's code and data have loaded.
  - Facebook Pixel / Google Analytics: their scripts now load on the
    visitor's first touch/scroll, or 4 s after the page has loaded —
    whichever is first. Every event (PageView included) is queued from
    the first moment and sent when they arrive, so nothing is lost.

  - vercel.json: hashed files (/assets/…) cached for a year

    manifest are never cached.
  - Pictures: the banner's first photo is high priority and not lazy;
    product card photos are lazy; brand/browse/avatar images got sizes
    and async decoding; the brand page's banner is high priority.
    Uploads were already compressed in the browser (products, banners,

5. DESIGN DECISIONS (made by me)
-------------------------------
  - Part 3: the cart slides down by the bar's height + the gap (77 px),
    so it lands exactly where the bar was, above the safe area. (Moving
    by the bar's own exit distance would have pushed it to the very
    bottom edge, against your "still visible, above the safe area".)
  - Part 3: the scrolled top bar's buttons keep their Batch 28 shadow,
    because you asked for that bar to stay as it is.
  - Part 4: the toast is a pill in the buy bar's glass, with a small bin
    icon; "Undo" is bold black (white in dark mode).
  - Part 4: if the same item was added again before Undo, Undo restores
    the removed line as it was (its quantity and place), not added on top.
  - Part 5: a backdrop is judged from the whole outer edge (≥60% one
    colour) rather than only the four corner pixels — Hamilton's logo has
    a blue letter edge in one corner and would otherwise not be cleaned.
  - Part 5: logos appear without a fade (a fade replaying after Back
    broke the "nothing animates after a page settles" rule).
  - Part 6: the still picture under the video is the logo on a calm grey
    (dark: near-black) surface until a preview frame exists.
  - Part 7: trackers load on first touch/scroll or after 4 s, instead of
    at once. Honest trade-off: a visitor who closes the page within
    those first seconds without touching or scrolling at all may not be
    counted by Facebook/Google (their PageView was queued but the script
    never arrived). Everyone who touches or scrolls is counted, and all
    other events are unaffected.
  - Part 7: the early banner request in index.html uses the public
    (anon) key that is already inside the app's code — it's meant to be
    public; the database rules still protect everything.


6. INDUSTRY-LEVEL SUGGESTIONS (not implemented)
-----------------------------------------------
1. Real image resizing (medium–large). Serve each photo at the size it's
   shown (e.g. a resizing CDN or Supabase's image transformations on a
   paid plan, plus srcset). Biggest remaining speed win on Home and the
   cheapest data for customers on mobile data.
2. Show Home from the phone's saved copy first, then refresh (medium).
   Repeat visitors (most of your ad traffic after the first click) would
   see the shop instantly instead of waiting for the network.
3. A slimmer first data request for Home (medium): only the fields the
   cards need, not every product's full description.
4. Run "Generate small images" and re-upload the category photos
   (small, you can do it today — see section 4).
5. Reviews / star rating near the price (medium) — still the biggest
   missing trust signal.
