1. WHAT I DID

PART 1 — Hero morph: rounded corners now animate
Cause: on a grid card the photo box itself has square corners. The rounding
comes from the card around it (18px corners that clip the photo). The
browser's "flying picture" copies only the photo box, so it flew as a sharp
rectangle, and the real round corners snapped in when it landed.
Change: a small new module (src/lib/heroCorners.ts) measures the corners you
actually SEE at both ends: card 17px (18px minus the 1px border), product
photo 0px, bento tile 18px. It clips the flying picture to those corners and
animates them from one end to the other. It uses the same 320ms and the same
easing as the morph. Works for grid, bento and search cards, for the in-app
arrow and the phone back button, and for opening.
Proof (numbers read from the browser on every frame, grid card):
  open:        17,17,13,10,7,5,4,3,2,1,1,0,0 ... (starts at 17, ends at 0)
  in-app back: 0,0,0,4,7,12,13,14,16,16,17 ... (starts at 0, ends at 17)
  phone back:  0,0,0,4,10,13,14,16,16,16,17 ...
The first frame equals the page you left, and the last frame equals the page
you land on. The size morph itself is unchanged, and so is everything else
about open/back.

PART 2 — Refresh starts at the top
Cause: on a fresh page load the router labels the first page a "Pop", the
same label a Back gets. The saved scroll position also survives a reload
(browser session storage). So a refresh was treated exactly like a Back and
jumped down.
Change (src/components/shared/PageTransition.tsx, src/lib/scrollMemory.ts):
  - Scroll is restored ONLY on a real Back/Forward. A reload or a fresh open
    always starts at the top. (The browser itself says how the page was
    loaded — "reload" vs "back_forward" — and that is now checked.)
  - While you scroll, the saved position is kept up to date (at most every
    150ms), so a later Back returns to where you really were.
  - Tapping the Home tab scrolls to the top and forgets the old spot.
Proof: the new tests fail on the old code exactly as you saw (reload landed
at 601px / 300px / 1202px) and pass on the new code (0px). Home and /search
both covered.

PART 3 — Variants: sizes, and the image follows the choice
Cause, from the live data for CeraVe Hydrating Cleanser:
  - Australia has only size "236" and Korea only "473". The Size row was
    hidden whenever a region had just one size.
  - The gallery always put EVERY variant photo first, ahead of the
    product's own photos. So the page opened on Korea's refill pouch, while
    the card showed the product's own photo (the green bottle). Picking
    Korea then showed the same pouch, so nothing changed. The hero morph
    flew the bottle into a pouch — the "pouch, bottle, pouch" you saw.
The ONE rule now used everywhere:
  - A card (grid, bento, search) shows the product's own first photo, which
    is the default option.
  - The product page opens on that same default option, so its first photo
    is the same photo. The morph lands on it and nothing changes by itself
    afterwards (loading variants later only adds photos at the END).
  - Picking another region/size shows that option's own photo first,
    falling back to the product's photos if it has none.
  - The cart and checkout thumbnails already followed this rule (the chosen
    variant's photo, else the product's).
  - With 2+ regions, the Size row always shows, even when that region has
    only one size (it is pre-selected, so you always see what size you're
    buying).
Proof: e2e test on CeraVe — the page opens on the card's photo and stays
there for 4 seconds; picking Korea shows the Size row, a new price and a new
photo; picking Australia brings both back. Unit tests cover the photo rule.

PART 4 — Cart buttons
Cause for "Beauty of Joseon Revive Eye Serum": it has a second size (10ml),
so its cart button did not add anything. It silently opened the product
page instead, which reads as "doesn't work". CeraVe Hydrating Cleanser and
La Roche-Posay Cicaplast Baume B5+ behaved the same way.
Change: for a product with options, the card's cart button now opens a small
"Choose options" sheet over Home. It shows the photo, name, price, stock and
the Region/Size chips (the same picker as the product page), plus Add to
Cart. You never leave the page. A short "Added to cart" toast confirms it.
Proof: a new e2e test taps the cart button on EVERY card on Home:
  104 cards — 94 added directly, 3 through the option sheet, 7 out of stock
  (their buttons are disabled on purpose). 0 failures.

PART 5 — "Track parcel on Steadfast" link
(a) New bookings: checked the whole path. Steadfast's booking reply contains
    tracking_link (https://steadfast.com.bd/tl/...). The Edge Function passes
    it on, the database function saves it, and the customer's order page
    uses it. The steadfast_tracking_link column exists in the live database
    (checked). No real booking was placed, so this is proven by reading the
    code and checking the database, not by a live parcel.
(b) Older orders: Steadfast's status endpoints return only the delivery
    status, never the link. The link only exists in the booking reply, so
    it cannot be fetched later. Those orders keep the generic tracking page.
    (The PDF is no longer in Downloads. This relies on what
    fix/steadfast-auto recorded from it.)
Change: one shared helper (src/lib/steadfastLink.ts) picks the link for both
screens. It only trusts https links on steadfast.com.bd. The admin order
screen now always shows the link: "Track parcel on Steadfast" when the
parcel has its own link, or "Track on Steadfast (generic page, enter the
tracking code)" when it doesn't.

PART 7 — Video Review player
  - The "Watch Review" row shows the video's real YouTube thumbnail, with a
    small plain-text "Reviewed on YouTube" label (not a link).
  - Tapping plays it inline, right there, full width, 16:9. No sheet, no
    fullscreen, no page change. Add to Cart stays on the page.
  - Embed: youtube-nocookie.com with controls=0, rel=0, modestbranding=1,
    playsinline=1, disablekb=1, fs=0, iv_load_policy=3.
  - A transparent layer covers the whole video, so taps never reach
    YouTube. Tap anywhere to play or pause, plus our own sound on/off
    button.
  - Until it actually plays, and whenever it's paused, our thumbnail covers
    the player. That hides YouTube's own start and pause screens (title bar,
    "more videos"). When it ends, it goes back to the thumbnail row.
  - Sound: it tries to start WITH sound (your tap allows it). If a browser
    refuses, it starts muted after 2.5 seconds and the sound button shows
    "off".
  - A product whose video link isn't a real YouTube link now shows no Video
    Review section (it used to open the link in a new tab — an exit).
Proof: e2e test on a phone-sized screen — the thumbnail is from i.ytimg.com,
the video really starts playing (within 15s, usually ~1.5s), and 10 taps
spread over the video (including all four corners, where YouTube's title
and logo sit) all land on our own layer. The page URL never changes and no
new tab opens.
Honest limits — what YouTube may still show:
  - While it plays, YouTube can briefly show its own title/channel strip or
    logo watermark along the top or corner, and occasionally a paid-promotion
    or age notice. They cannot be switched off, but they cannot be tapped
    either (our layer is on top).
  - On iPhone Safari, turning sound on with our button may be refused by the
    browser after a muted start. Android Chrome is fine in testing.

5. DESIGN DECISIONS
-------------------
- Card cart button for products with options: a quick "Choose options"
  sheet instead of opening the product page. It's the standard shop pattern
  (quick-add), and it keeps the shopper on the grid. Add to Cart is the only
  orange thing in it; prices are near-black.
- One photo rule (see Part 3), so the card, the product page, the morph and
  the cart always agree.
- Size row shown even with one size once there are regions — so the size
  being bought is always visible.
- Video starts with sound (the tap is a clear "I want to watch"), falling
  back to muted only if the browser refuses. Our thumbnail covers YouTube's
  pause screen, so pausing never exposes YouTube's "more videos" panel.
- Invalid video links: section hidden rather than opening a new tab.
- Bangla place names: hidden but still searchable, so a customer typing in
  Bangla isn't stuck.
- History notes: translated when displayed (works with no SQL) plus an
  optional migration, so nothing depends on SQL being run.
