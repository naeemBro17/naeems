1. WHAT I DID
============================================================

PART 1 — The new invoice
  - One A4 page, matched to the approved PDF. The TOP THIRD is the parcel
    label: NAEEM'S + "Invoice", the Steadfast consignment ID in big
    letters with a barcode under it, tracking code, "Steadfast Courier ·
    Regular", and a box "DELIVER TO" with name, phone, address,
    thana/district and a black panel "COLLECT (COD) ৳4,079".
  - The rest is the invoice: Sold by / Billed to / Invoice no., the items
    table (Unit price, Qty, Discount, Amount — no SKU), amount in words
    ("Four thousand seventy-nine taka only", lakh and crore work), the
    totals, the community box with the QR code to the Facebook group,
    and the thank-you footer.
  - The COD amount follows the same rule as Steadfast booking: pay-later
    orders show ৳0 "Customer pays later" and the last line "Balance due
    (pay later)"; fully paid orders show ৳0 "Paid — do not collect";
    advance payments show one "Paid in advance (bKash)" line per method.
  - Not booked yet: "Not booked yet" + "Book with Steadfast to print the
    label", no barcode; the invoice part still prints.
  - Long orders continue on page 2 ("NAEEM'S · Invoice INV-NM-xxxx · page
    2 of 2"); totals, community box and footer go on the last page.
  - Fonts: Plus Jakarta Sans (the site's font) and Hind Siliguri for ৳ and
    Bengali, built into the PDF, so it prints the same everywhere.
    Bengali names and addresses come out correctly shaped (joined
    letters, vowel signs) — checked in samples/bengali-name.png.
  - Where it is used: the admin order page "Invoice" button, and the
    customer's "Download invoice" on the Order placed page (their copy
    shows the order number instead of the consignment, never staff notes).
    The old plain invoice code (jsPDF, "Tk" instead of ৳) is removed.
  - Settings → Invoice (Super Admin): shop phone/WhatsApp (blank = the
    Checkout WhatsApp number), shop city ("Dhaka, Bangladesh"), community
    QR link (default: the Facebook group), title and two lines, and a
    switch "Show community box" (On). Blank fields use the default.

PART 2 — Printing
  - ONE ORDER: order page → Other actions → Invoice. A small window
    makes the PDF, then: Print (orange), Download PDF, and Share (when
    the device can). On a PC, Print opens Chrome's print window. On a
    phone, Print opens the share sheet — choose Print there (Android).
  - MANY ORDERS: Orders → the ⋮ menu → "Print invoices". Tick orders, or
    tap "All booked today, not printed yet (N)". Then "Print N invoices"
    makes ONE PDF, one order per page, lowest order number first.
  - Printing, downloading or sharing marks the orders as printed: a small
    grey "Printed" under the order in the list, and "Invoice printed" with
    the time in the order's History. Re-printing is allowed. (This part
    needs the database addition below.)

HOW TO PRINT
  - Paper: A4. In the print window choose Scale: "Actual size" / 100%,
    NOT "Fit to page" — a shrunk barcode may not scan. (The PDF also asks
    printers not to shrink it.)

HOW TO FOLD
  - The two faint dashed lines split the page in thirds. Fold the lower
    two-thirds BACKWARDS along both lines (like a letter), so the label —
    the top third with the barcode and "Deliver to" — stays on the
    outside. Tape it on the box with the label facing up.

-- ============================================================
-- Batch 37 — new invoice and bulk print (reports/batch-37.txt).
--
--   app_settings rows       the invoice settings (Admin → Settings →
--                           Invoice). Blank = the default the website
--                           uses: shop phone = the Checkout WhatsApp
--                           number, "Dhaka, Bangladesh", the Facebook
--                           group link and texts, community box On.
--   order_invoice_prints    one row each time an order's invoice is
--                           printed (re-printing is allowed).
--   record_invoice_prints() remembers a print and adds "Invoice printed"
--                           to each order's History.
--
-- Who: anyone allowed to see orders (staff_can('view_orders'); the Super
-- Admin always) can print and read the print marks. Nobody can write
-- order_invoice_prints directly — only through record_invoice_prints().
--
-- Additive only: new rows (existing settings are never overwritten), one
-- new table, one new function. Nothing is changed or dropped. Safe to run
-- more than once.
-- ============================================================

BEGIN;

INSERT INTO app_settings (key, value) VALUES
  ('invoice_shop_phone', ''),
  ('invoice_shop_city', ''),
  ('invoice_community_link', ''),
  ('invoice_community_title', ''),
  ('invoice_community_line1', ''),
  ('invoice_community_line2', ''),
  ('invoice_show_community', 'true')
ON CONFLICT (key) DO NOTHING;

CREATE TABLE IF NOT EXISTS order_invoice_prints (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  order_id    uuid NOT NULL REFERENCES orders(id) ON DELETE CASCADE,
  printed_at  timestamptz NOT NULL DEFAULT now(),
  printed_by  uuid DEFAULT auth.uid()
);

CREATE INDEX IF NOT EXISTS order_invoice_prints_order_idx ON order_invoice_prints (order_id, printed_at DESC);

ALTER TABLE order_invoice_prints ENABLE ROW LEVEL SECURITY;

DROP POLICY IF EXISTS "order_invoice_prints_staff_read" ON order_invoice_prints;
CREATE POLICY "order_invoice_prints_staff_read"
  ON order_invoice_prints FOR SELECT TO authenticated
  USING (staff_can('view_orders'));

REVOKE ALL ON order_invoice_prints FROM anon;
REVOKE INSERT, UPDATE, DELETE ON order_invoice_prints FROM authenticated;
GRANT SELECT ON order_invoice_prints TO authenticated;

CREATE OR REPLACE FUNCTION record_invoice_prints(p_order_ids uuid[])
RETURNS integer
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public
AS $
DECLARE
  v_order record;
  v_count integer := 0;
BEGIN
  IF NOT staff_can('view_orders') THEN
    RAISE EXCEPTION 'Not authorized.';
  END IF;
  IF p_order_ids IS NULL OR array_length(p_order_ids, 1) IS NULL THEN
    RETURN 0;
  END IF;
  IF array_length(p_order_ids, 1) > 500 THEN
    RAISE EXCEPTION 'Too many orders at once.';
  END IF;

  FOR v_order IN SELECT id, status FROM orders WHERE id = ANY (p_order_ids) LOOP
    INSERT INTO order_invoice_prints (order_id, printed_by) VALUES (v_order.id, auth.uid());
    PERFORM order_history_line(v_order.id, v_order.status, 'Invoice printed');
    v_count := v_count + 1;
  END LOOP;
  RETURN v_count;
END;
$;

REVOKE ALL ON FUNCTION record_invoice_prints(uuid[]) FROM PUBLIC, anon;
GRANT EXECUTE ON FUNCTION record_invoice_prints(uuid[]) TO authenticated;

COMMIT;

5. DESIGN DECISIONS
============================================================
  - PDF library: switched from jsPDF to pdf-lib + fontkit (free, MIT).
    jsPDF cannot shape Bengali; fontkit does. The PDF code (~600 KB) and
    fonts (~1.6 MB) load only when an invoice is made, never for shoppers
    browsing, and the browser keeps them after the first time. Fonts are
    not in the offline cache.
  - "Steadfast Courier · Regular" as in the approved mockup — every parcel
    is booked as Steadfast's standard home delivery.
  - The QR code sits on a small white square inside the grey box (the
    mockup had it straight on grey) — better contrast for phone cameras.
  - Item text is 9 pt (mockup size) so normal product names fit on one line.
  - "Booked today" = the order's "shipped" History line is from today,
    Dhaka time, and it has a consignment ID. No change to Steadfast
    booking was needed.
  - Any of Print / Download / Share counts as "printed" (you cannot know
    whether the paper actually came out).
  - The customer's copy uses the same design (as the brief asked: replace
    the old invoice everywhere), showing their order number in the label
    area; bKash website orders show as paid (they pay the full total).

6. INDUSTRY-LEVEL SUGGESTIONS (not done)
============================================================
  1. Thermal label size (medium): many shops print 4×6 in labels on a
     thermal printer — faster and no folding. The label part could be
     made as a separate 4×6 page. Saves time on busy days.
  2. Print straight after booking (small): "Book with Steadfast" could
     offer "Print label now" in the same step.
  3. Invoice number series (small): today the invoice number is the order
     number with INV-. If Naeem later needs VAT-style continuous invoice
     numbers, a separate counter is needed.
  4. Scan check before dispatch (medium): scanning each parcel's barcode
     with the phone camera on a "Dispatch" screen would catch a wrong
     label on a wrong box before the rider leaves.
