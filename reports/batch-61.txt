======================================================================
1. WHAT I DID
======================================================================
Nothing in the shop changed: only test files, test helpers, e2e/sql/
scripts and the report. No file in src/, no migration and no
Edge Function was touched.

 • Database tests no longer re-create old functions. Batch 45 to 55.1
   used to paste their old migration in front of the test, which rebuilt
   an older version of place_order and others on top of today's database
   (that is why they broke). Now every database test runs against the
   functions that are live today, inside one transaction that is always
   rolled back. Settings a test needs are set INSIDE that transaction
   (advance discount 0.5%, order limit, money start date, Inventory mode),
   so the live shop's own values no longer matter.

 • Test orders never use a real product any more. With Inventory mode On,
   every old test order took units from your real lots, and the tests
   failed whenever the shop ran low ("Only 0 of … left in stock"). A new
   helper makes a hidden made-up product (SKU E2E-ORD-…, "keep selling",
   no lots), shows it in the shop only for the second the order is placed,
   and deletes it at the end of the run. Nothing real is taken.
   Where a test needed real stock numbers, the stock is answered in the
   browser (Batch 33) or checked in a rolled-back database test.

 • Tests that read live things that have changed now set up what they
   need: the books shown as "not confirmed" in the browser (opening
   balances), the "Mode Off" note shown only when Mode is Off, your
   "Show rider's phone" switch read as it is, etc.

 • The two timing flakes are fixed at the cause, not by longer waits:
   the video tests now use a tiny stand-in YouTube player (they waited for
   a real YouTube video over the internet), and the card stepper test
   moves the card clear of the floating cart button, which was covering
   its "+" button.

 • New rolled-back database tests: Restock (Add / Set to / log in Mode
   Off, refused in Mode On) and Reopen a cancelled order (status back,
   stock taken again, history, Activity Log, refusals).

 • The test login's name had been changed to "E2E Batch 52.1" by an old
   checkout test; I put it back to "E2E Test Customer" (test account only)
   and that test now restores it after itself.

 5. The checkout's "Save and continue" writes the typed name and address
    onto the customer's own profile. Fine for real customers, but worth
    knowing: it changed the test login's name for weeks.
 6. The old tests' real orders (Inventory mode On) took units from your

======================================================================
5. DESIGN DECISIONS
======================================================================
 • Made-up products are hidden and shown only for the moment of the order
   (the test rpc() helper does it for every order call that names one),
   so a shopper never sees "E2E Order Product". Deleted in global teardown
   (any run's, by the E2E-ORD- SKU).
 • Where a test only LOOKS at a product page (photos, description,
   video), it opens a real buyable product and never saves anything.
 • Batch 48's promo + advance case uses 2 items so ৳1,000 or more is paid
   in advance (Batch 60 rule); the ৳999 / ৳1,000 edge stays tested in
   e2e/sql/batch-60.sql.
 • Batch 50 / 54: the start date is moved inside the rolled-back
   transaction, so old Kaarbar bills count (Batch 58 rule: only on or after
   the start date) and the checks compare with the shop's own old bills.
   The balance check is now expected to move by the old bills' profit —
   exactly what Batch 58 wrote it should do.
 • Batch 46 / 47: "every payout adds up" now counts only payouts that have
   lines, the same way the Batch 57 health audit counts it; the stuck
   payout is reported above instead of failing an old migration check.
 • Batch 26 Restock: the browser test follows the live Inventory mode;
   saving is tested in Mode Off inside a rolled-back transaction.

 5. Small — write the "--project=serial --no-deps" tip into CLAUDE.md's

 6. Medium — a monthly "health" script (outside the test suite) for live
    data checks like broken photos and stuck payouts, so the e2e suite
    tests the code and the health script watches the data.
