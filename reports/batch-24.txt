PART 3 — Order number format

a live line "Next order will be: NM-1047".

PART 4 — Delete orders, with a Safety Lock + clean-out of test orders
  - Normal rule (everyone): only Pending orders, or Cancelled orders that
    were never booked on Steadfast, can be deleted. Moderators need the
    "Delete early orders" permission for this.
  - Any later stage (Confirmed, Shipped, Delivered, booked on Steadfast):
    blocked for everyone, including you, while the lock is on.
  - "Delete order" button on the order screen, and checkboxes + "Delete
    selected" on the Orders list. Checkboxes only appear on orders you may
    delete right now. On a blocked order the screen says: "Locked: turn on
    'Allow deleting orders at any stage' in Safety Locks."
  - The confirmation is plain English; for more than one order you must
    type DELETE. If a parcel is booked on Steadfast it warns: "This parcel
    is booked on Steadfast (consignment …). Deleting here does NOT cancel
    it on Steadfast. Cancel it on the Steadfast portal too."
  - Stock is put back exactly once (an already-cancelled order already
    had its stock put back, so it is not added again).
  - The order, its items and history are removed; the Activity Log keeps
    the order number, customer name, total and who deleted it.
  - The old delete function the live site still uses now follows the same
    rule, so it can't be used to get around the lock.
Proof: e2e tests 6, 7 and 8.

HOW THE SAFETY LOCK WORKS (3 lines):
  1. Settings → Safety Locks → switch on "Allow deleting orders at any
     stage"; type your password again.
  2. For 15 minutes you can delete any order; a red bar at the top shows
     the countdown and a "Turn back on now" button.
  3. It turns itself back on after 15 minutes or when you log out. The
     database checks it on every delete.

PART 5 — Edit item prices on an order (only you)
On the admin order screen each item has "Edit price" (any order status):
type a new unit price, or tap "Free" (৳0). The database recalculates the
line, subtotal, discount (never more than the subtotal), and the total /
COD amount; nothing is taken from the browser's maths. Each change goes
into the order history ("Price of X changed ৳a → ৳b (total ৳c → ৳d)") and
the Activity Log. Moderators never see it; the database refuses it for
them. The customer's My Orders page and the invoice show the new prices.
Proof: e2e test 9.

STEADFAST COD — MUST BE CHANGED ON THE PORTAL. Steadfast's API has no way
to edit a booked parcel or its COD amount (their official package only
offers create order, bulk create, status checks and balance). So before
saving a price on a booked order the screen warns: "This order is booked on
Steadfast. The COD amount there will not change automatically. After
saving, change the COD amount on the Steadfast portal too." After saving it
reminds you again.

PART 6 — Customer sees the delivery status in My Orders
The order page shows the progress in plain words: Order placed →
Confirmed → Handed to courier → On the way → Delivered, with "Last update
<date time>" (Bangladesh time). When it happens: Cancelled, Returned (the
courier sends the parcel back) or On hold ("We will contact you"). The My
Orders list shows the same one-word status. It uses only the status
already saved by the Steadfast functions; the customer's browser never
contacts Steadfast. Courier notes and internal fields are not shown. The
"Track parcel on Steadfast →" link is unchanged. A customer can only ever
see their own orders (checked in the test).
Proof: e2e test 10, plus unit tests for every Steadfast status.

5. DESIGN DECISIONS
-------------------
  - One source of truth for roles: moderators are role "moderator" in the
    existing profiles table; a new staff_members table only holds username,
    permissions and the disabled switch.
  - The Safety Lock's password check is a real re-login: the login token
    records when the password was last typed, and the database only
    accepts it if that was under 5 minutes ago.
  - Moderators can't change prices anywhere (manual orders are always at
    the normal price; delivery-fee edits stay yours). Money changes are
    Super Admin only.
  - "View customers" maps to the existing Wholesalers list (read only) and
    the phone look-up. There is no separate customers page yet.
  - Deleting a delivered order (lock off) also puts its stock back, as
    asked ("restore stock for every item whose stock had been taken").
  - Orange stays on one main action per screen (e.g. "Add moderator",
    "Save"); the Safety Lock bar and delete warnings are red; everything
    else is neutral.
