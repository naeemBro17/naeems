HOW A CUSTOMER ASKS FOR A WALLET, AND HOW YOU OPEN IT
 • Every wallet is now CLOSED until you open it. The SQL opens it
   automatically for the customers who already had wallet money or a
   request (3 customers today), so nobody with money loses anything.
 • A customer with a closed wallet sees, on Account, "MY WALLET · Save for
   the glow you love · Invite only · Tap to learn more". Tapping opens the
   new jar story (dark page, "SAVE FOR THE GLOW YOU LOVE" in the Anton
   font, coins dropping into a jar that fills a step with each one), the
   badge INVITE ONLY, three promises and a green "Ask us to open my
   wallet" button. It opens WhatsApp to your shop number with:
       হাই, আমি আমার Wallet চালু করতে চাই।
       নাম: <their name>
 • You open it on the customer's admin page, WALLET card: switch
   "Wallet open". "Add to wallet" also opens it by itself. Any money that
   comes into a wallet (also an over-paid / cancelled order's extra) opens
   it, so a balance is never hidden.
 • Closing a wallet that still has money is refused: "This wallet still
   has ৳2,000. It can be closed when the balance is ৳0." (also refused
   while a request is waiting).
 • Open but empty: the same jar story with "YOUR WALLET IS OPEN", two
   promises and the orange Add money. With money or history: Batch 60's
   balance page, its last line now "Save for the glow you love."
 • A closed wallet's "I sent money" is refused by the database too:
   "Your wallet isn't open yet. Message us on WhatsApp and we'll open it."
   Checkout's "Use wallet balance" shows only for an open wallet.
 • Rejected request text: "Your ৳3,000 wasn't added. The payment didn't
   match our records. Message us on WhatsApp and we'll sort it out." in a
   plain grey box with a small red dot (WhatsApp and Dismiss stay).
 • "Discard changes?" after Add to wallet (customer 01912809053): the
   cause was that the customer page treated typing anywhere in it as
   unsaved, and a sheet's typing reaches the page too. Confirm sheets
   (Add to wallet, Confirm, Reject, Correct) and the WALLET card save on
   their own, so the page now ignores them. Also fixes the same thing for
   the other confirm sheets on that page.
 • Home "Needs attention" never shows "p:f05af719-…" any more: name, else
   phone, else "A customer" (in the database and on the screen).

   Crossed eye = hidden: the row says "Hidden from the shop".

   checkout ("This size is no longer available.") and never sends it to

   orders, invoices, lots and reports still see it.

FASTER WHEN YOU COME BACK
 • The shop (products, settings, sizes), the customer's wallet and My
   Orders, and admin Home, Orders, Customers and Money keep their last
   good copy in the phone. Opening shows that copy at once, then the
   fresh one replaces it quietly. Coming back to the app reads again only
   if the copy is older than 60 seconds. Admin money numbers shown from
   the copy say "Updating…" until the fresh ones arrive.
 • The copies are only for showing: placing orders, payments, stock and
   checkout's wallet always use fresh data (checkout never uses the
   copy). Signing out deletes every copy; a new app version starts fresh.
 • Measured (npm run preview, Storage mocked, one try each, this PC):
     Home, reopen:          no copy 1.16 s to first products · with copy 0.59 s
                            requests 8 / 479 KB both (the fresh read still happens)
     Admin Orders, reopen:  no copy 1.53 s to first order · with copy 1.00 s
                            requests 21 / 673 KB both
     Back in the app within 60 s: 0 requests (the wallet used to read
                            again on every focus; now at most once a minute)
   Honest note: the win is speed you SEE (the screen no longer waits for
   the network; on a slow phone connection that is seconds, not half a
   second), not fewer bytes on a reopen. Bandwidth only drops for quick
   returns (under 60 s).

    SFC-33372895 (৳6,836, paid 19 Nov) is read again and matched the
    normal way. Edge Functions deployed. Balance check stays green.
 2. Reopen a "Keep selling" order at stock 0 now works, like placing it
    (Mode On: the units are "sold without stock"; Mode Off: "bought after
    the order"). A product without Keep selling is still refused.
 3. Restock is hidden while Inventory mode is On; where it can still be
    reached the message is "Stock now comes from lots. Add a lot to change
    it."
 4. Names in Needs attention (above).

5. DESIGN DECISIONS
======================================================================
 • Money into a closed wallet (an over-paid / cancelled order's extra)
   opens it automatically: a balance must never be hidden.
 • Closing is also refused while a request waits (otherwise the
   customer's request would hang on a closed wallet).
 • Before the SQL is run every wallet counts as open (keeps Batch 60
   working until you run it).
 • Hidden sizes: filtered in the database (view and table for customers /
   visitors) and also on screen for staff browsing the shop. Combos'
   "Add products" offers only the sizes the shop shows.
 • Two-column Edit product only on the Edit product page (≥ 1024 px); the
   quick-edit sheet in the shop stays one column so nothing is cramped.
 • The preview's title follows the tab (About this product / How to use /
   Key ingredients).
 • Editor = product page text on phones up to 599 px: same width (the
   editor reaches into the card's side padding), 13.5 px, line height 1.7,
   and font ligatures on (the editor library turns them off, which made
   its letters slightly narrower).
 • Price labels shortened to "Retail ৳ / Offer ৳ / Wholesale ৳" so three
   fit side by side on a phone; same fields and ids.
 • Combo arrows (↑ ↓ ×) are plain text symbols, not emoji.
 • Copies kept in localStorage (wrapped in try / catch), keyed by app
   version and by who is signed in; checkout never reads one.
 • batch-62.spec.ts runs in the "serial" group (its database test changes
   settings inside a rolled-back transaction).
 • Tests changed for the new behaviour: batch-26 (no Restock in Mode On),
   batch-51 (Pre-orders text without the dash), batch-60 (the old story
   tests moved to batch-62; new rejected text), e2e/sql/batch-60.sql
   (opens the test customer's wallet inside its transaction).
