FIX NAEEM CAN RUN
-----------------
It does four things:
  - removes NM-3321's link to the phantom L-000 row
  - deletes that phantom row
  - sets L-017 back to 100 ml (0 left, value ৳270)
  - adds one history line on L-017: "Lot edited: units 200 → 100 ...",
    the same kind of line the app writes when you edit a lot
The shop's stock then updates by itself to 0 / out of stock, because
Inventory mode is ON. Keep Inventory mode ON when you run this.

Step 1. Look first (changes nothing). Paste and run:

  SELECT 'link' AS what, x.id::text AS id, o.order_number AS ref,
         x.units AS qty, x.units_back AS remaining, NULL::numeric AS value
  FROM order_item_lots x JOIN orders o ON o.id = x.order_id
  WHERE x.lot_item_id IN ('06d80f05-d7c6-4829-a0a4-7dc855ba8d50',
                          '5bae8227-2d12-40e8-909a-ac2fc7872ef2')
  UNION ALL
  SELECT 'lot row', li.id::text, l.code, li.qty, li.qty_remaining, li.buy_value_bdt
  FROM lot_items li JOIN lots l ON l.id = li.lot_id
  WHERE li.product_id = '53bc91d4-327d-468e-b2af-f9774787a3af'
  UNION ALL
  SELECT 'shop stock', id::text, stock_status, stock_quantity, NULL, NULL
  FROM products WHERE id = '53bc91d4-327d-468e-b2af-f9774787a3af'
  ORDER BY 1, 3;

Step 2. The change. Paste ALL of it and run it once:

  BEGIN;

  DELETE FROM order_item_lots
  WHERE id = 'cfd438cd-bf4f-48c1-b3d0-485591ff339e'
    AND order_item_id = '4660594f-f475-4a85-ac8a-8f50b33d4019'
    AND lot_item_id = '06d80f05-d7c6-4829-a0a4-7dc855ba8d50'
    AND units = 100 AND units_back = 0;

  DELETE FROM lot_items
  WHERE id = '06d80f05-d7c6-4829-a0a4-7dc855ba8d50'
    AND product_id = '53bc91d4-327d-468e-b2af-f9774787a3af'
    AND qty = 473 AND qty_remaining = 373;

  UPDATE lot_items
  SET qty = 100, qty_remaining = 0, buy_value_bdt = 270.0000
  WHERE id = '5bae8227-2d12-40e8-909a-ac2fc7872ef2'
    AND product_id = '53bc91d4-327d-468e-b2af-f9774787a3af'
    AND qty = 200 AND qty_remaining = 100 AND buy_value_bdt = 540.0000;

  INSERT INTO stock_movements (lot_item_id, movement_type, qty, reference, reason, created_by)
  SELECT '5bae8227-2d12-40e8-909a-ac2fc7872ef2', 'purchase', -100, 'L-017',
         'Lot edited: units 200 → 100 (Fix 69.2: NM-3321 was sold before 13 Nov)',
         '13393250-4483-481d-9d50-46786d1b6771'
  WHERE EXISTS (SELECT 1 FROM lot_items
                WHERE id = '5bae8227-2d12-40e8-909a-ac2fc7872ef2'
                  AND qty = 100 AND qty_remaining = 0);

  SELECT set_config('request.jwt.claims',
    '{"sub":"13393250-4483-481d-9d50-46786d1b6771","role":"authenticated","aal":"aal2"}', true);

  DO $$
  BEGIN
    IF abs((money_position() ->> 'difference')::numeric) >= 0.01
       OR (SELECT stock_quantity FROM products WHERE id = '53bc91d4-327d-468e-b2af-f9774787a3af') <> 0
       OR EXISTS (SELECT 1 FROM lot_items WHERE product_id = '53bc91d4-327d-468e-b2af-f9774787a3af' AND qty_remaining <> 0)
       OR EXISTS (SELECT 1 FROM lot_items WHERE id = '06d80f05-d7c6-4829-a0a4-7dc855ba8d50')
       OR NOT EXISTS (SELECT 1 FROM stock_movements WHERE lot_item_id = '5bae8227-2d12-40e8-909a-ac2fc7872ef2'
                      AND reason LIKE 'Lot edited: units 200 → 100 (Fix 69.2%') THEN
      RAISE EXCEPTION 'STOP: the fix did not come out right. Nothing was saved.';
    END IF;
  END $$;

  SELECT money_position() ->> 'difference' AS difference_now;

  COMMIT;

4. FOUND ALONG THE WAY (not fixed)
=====================================================================
- The audit's FIX 1 format had a trap. When it ends with COMMIT, the
  change is already saved by the time you read difference_now. So
  "change COMMIT to ROLLBACK and run again" cannot undo it. A second run
  just matches no rows. I added the STOP check so the block undoes
  itself if the result is wrong. Use this pattern for future fixes.
- NM-3321's 100 ml line keeps its cost row (৳2.70/ml, source "lots")
  even though it will no longer take from a lot. It is before 13 Nov, so
  it is not in profit, and the opening counts it from the order, not
  from this row. It does no harm, but it is slightly untidy.
- The same bug (an edit of an old order putting a whole bottle back into
  L-000) can happen again on any order from before 13 Nov. The audit's
  suggestions in its section 6 still apply.
- Test orders NM-7564 and NM-7676 (from a test login) took this real
  stock on the live shop and then cancelled. They gave it all back, but
  tests creating orders against real live stock is a risk.
- Deleting the phantom L-000 row also deletes its 8 history lines (the
  "back from order" line, NM-3321's sale and give-back, and the test
  orders' sale and give-back). They only describe the phantom. The
  Activity Log entry for your NM-3321 edit stays.
- UI text with a tick character in src/ (not changed, as asked):

  There are no others (no ✔, no escaped ticks).

5. DECISIONS
=====================================================================
- Delete the phantom L-000 row instead of keeping it at 0 remaining.
  Keeping it is not possible honestly. The database requires qty above 0,
  and the 13 Nov opening counts every L-000 row by its full qty. A kept
  row would still add 473 ml (৳1,277.10) to the opening, and the gap
  would stay. The row never matched anything on the shelf, so removing
  it is the honest record. The trail of what happened stays in the
  Activity Log, this report, and the new L-017 history line.
- L-017 set to 100, not left at 200. With NM-3321 counted as "sold
  before 13 Nov", only Lamia's 100 ml comes from L-017. L-017's own
  history shows it held 100 when Lamia bought. The 100 → 200 edit at
  00:34 on 26 Nov was made to cover NM-3321. So 100 makes it end at 0,
  matching the shelf.
- I added the L-017 history line in the app's own wording ("Lot edited:
  units 200 → 100"), so the lot's history page shows the correction.
- I did not touch the shop stock directly. With Inventory mode ON, the
  app's own trigger sets it to 0 / out of stock. That is safer than
  writing it by hand, and the STOP check confirms it happened.
- Tick text: changed to plain "Saved", which is what every other admin
  screen already shows (AdvanceDiscountPanel, CustomerNotes, the edit
  sheets). The tests now look for the exact text "Saved", so they cannot
  match a longer text that only contains that word.
