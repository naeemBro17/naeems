4. WHAT I FOUND ALONG THE WAY
======================================================================
 • THE SUPABASE COMMAND-LINE LOGIN ("password authentication failed for
   user cli_login_postgres"). Nothing was wrong with the login itself:
   a single query worked every time. The command line signs in with a
   temporary login and gives it a NEW password on every run. When two test
   files ran database scripts at the same moment, they changed each
   other's password and one failed. I proved it: 3 harmless "select 1"
   queries started together, only 1 answered. Fix, in the shared test
   helper e2e/helpers/sqlRunner.ts: only one run signs in at a time on this
   computer (a lock held for the first 4 seconds of a run, so scripts can
   still overlap, which batch-39's two-orders test needs), and a run that
   could not sign in is tried again (up to 3 times). No database change;
   nothing on the live shop was touched.
 • batch-32 Part 1 also checks "we landed on the new order's page" with a
   pattern that /admin/orders/new itself matches. It passes now that the
   toast check is fixed, but it is still loose. Worth tightening one day.
 • A smaller side note: "npx --no-install supabase" no longer works on this
   computer (the project now asks for CLI 3.3.0, which is not downloaded).
   The tests do not need it: they use the copy (2.119.0) in the npx cache.
 • The admin colour --adm-thumb (the photo tile) has no dark version, so
   in dark mode the no-photo bottle tile is light. The CSS I was given
   uses it as-is; see the dark frames.
 • The leftover changed screenshots / PDFs from older batches' test runs
   (reports/batch-33 … batch-60 screens, public/sitemap.xml) were already
   in the working folder; I left them uncommitted.

======================================================================
5. DESIGN DECISIONS
======================================================================
 • The CSS is the approved CSS, values unchanged. I added one small block
   after it (in the same file), only for this page: the search field
   inside the search box has no box of its own (the box is drawn by the
   approved CSS, the old orange focus glow was showing inside it), and the
   small text buttons "Free" and "Change" are grey instead of orange. Both
   so Create order really is the only orange thing.
 • batch63.css is imported in AdminPage.tsx right after admin.css, not in
   main.tsx: the admin styles load later and would otherwise override the
   new ones.
 • "Secondary" buttons: there is no adm-btn--secondary in the admin, so
   Paste and Fill the form use adm-btn--ghost (outlined, neutral).
 • "N items" counts order lines, not packs (a line sold in loose ml would
   make a sum meaningless).
 • The order line photo uses the small copy; only when a product has no
   small copy yet does it fall back to the photo it showed before (so no
   line loses its picture). The search rows never fall back to the big
   photo: they show the bottle drawing instead.
 • The fraud check and "Account found" sit between Phone and Alternative
   phone, as in the mockup. For that the shared customer fields got one
   more optional slot (afterPhone), used only by New order.
 • "Admin note" is the card title and the field's label at the same time.
   The Customer search box keeps a hidden label "Customer" for screen
   readers (the card title already says it).
 • The combo editor keeps the old plain result rows (photos are turned on
   only for New order and Edit order).

======================================================================
6. INDUSTRY-LEVEL SUGGESTIONS
======================================================================
 1. Keyboard use of the result lists (medium impact, small). Arrow keys
    and Enter do not move through the customer / product results yet. When
    you type many orders on a computer, this saves a mouse trip per item.
 2. Remember a half-typed order (medium impact, medium). If the phone
    reloads the page (low memory, a call), the whole form is lost. A draft
    kept on the device for an hour would protect a long order.
 3. Dark-mode photo tile (small impact, small). Give --adm-thumb a dark
    value so empty photo tiles do not glow in dark mode.
 4. Barcode / SKU search for staff (medium impact, medium). Searching by
    name works for 150 products; scanning or typing the internal code
    (admin only) is faster at the counter.
